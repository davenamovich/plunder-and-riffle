Best Replit runtime setup

You want 3 long-running processes conceptually, but inside one Replit project:

Next.js web app

Worker loop

Moltis process

Since Replit likes a simple startup flow, wire it so one command starts all three.

package.json scripts

Use something like this:

{
  "scripts": {
    "dev": "concurrently \"next dev\" \"tsx workers/index.ts\" \"tsx scripts/start-moltis.ts\"",
    "build": "next build",
    "start": "concurrently \"next start\" \"tsx workers/index.ts\" \"tsx scripts/start-moltis.ts\"",
    "db:push": "prisma db push",
    "db:generate": "prisma generate",
    "db:seed": "tsx prisma/seed.ts"
  }
}

You’ll need:

npm install concurrently tsx

Exact startup behavior
scripts/start-moltis.ts

This script should:

check if Moltis is already running

if not, spawn it as a child process

wait for health check

log success/failure

workers/index.ts

This should:

start a loop

run every 15–30 seconds for lightweight checks

dispatch heavier jobs every few minutes

Worker schedule example

every 30s: check queued rotator activations

every 30s: expire ended slots

every 5 min: ingest lead candidates

every 5 min: batch classify

every 10 min: draft comments

every 30 min: roll up metrics

every 24h: reset daily lead cap

Recommended database choice in Replit

Use Prisma here.

Why:

faster for MVP

clearer schema management

easier seed/setup

good fit for one-agent build

less friction than Drizzle for this specific use case

So the project should use:

prisma/schema.prisma
lib/db.ts

with lib/db.ts like:

import { PrismaClient } from "@prisma/client";

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

export const db =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: ["error", "warn"],
  });

if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = db;
How Moltis should fit in this structure
Do NOT do this

put rotator logic inside Moltis

let Moltis decide payouts

let Moltis own referrals

let Moltis directly mutate critical slot/accounting truth

Do this

Moltis should live in:

services/moltis/

and only handle:

scoring requests

drafting requests

future keyword/ICP generation helpers

guarded action planning
